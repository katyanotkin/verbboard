# Don't remove existing content that has no problem

Owner rule (2026-11-05): the Russian example rework dropped good sentences (for example "Мне показалось, что…") only to fit
the 7-example split and a one-neuter-past cap. Existing content without a problem stays.

## Steps

1. Classify every existing item before changing a set: PROBLEM (wrong form or tense, calque, unnatural or bookish,
   wrong translation, forced neuter, too short to teach) or FINE. Only PROBLEM items may be replaced or removed.
2. Count and distribution targets are goals for what to ADD, not reasons to delete. Let a set grow past the target
   (tool caps permit it) rather than drop a fine sentence. Raise the cap when needed.
3. When a rule in a prompt or brief would force a deletion (a cap, a per-tense quota), tell the owner the conflict
   before applying, and default to keeping the item.
4. Briefs to agents must say: "keep every existing example that has no problem; list each removal with its reason".
   Reject results that remove without a stated problem.
5. The report lists removed items and their reasons so the owner can audit them.

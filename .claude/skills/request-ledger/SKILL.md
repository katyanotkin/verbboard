# Request ledger

Origin: the Plus request thread. A message had four numbered asks (email promise, About page, users
collection, request on every Plus page) and parts were missed; a later wording change was also
misread (kept "There is no email" instead of the exact text given).

## Steps

1. Split the message into numbered atomic asks. Quote exact wording for any copy/text ask; never
   paraphrase it. Mid-turn messages add new rows; they do not replace old ones.
2. Keep the ledger in the task list. Each row ends as done (with evidence: file, test or URL),
   deferred (owner told why), or declined (owner told why).
3. When two asks conflict or one changes an earlier decision, restate the final decision in one line
   before building.
4. Before the final report, walk the ledger. Report each row's status in order; do not summarize
   around gaps.
5. When the owner points out a missed request or a misunderstanding: fix it, then follow the
   `correction-to-skill` skill.
